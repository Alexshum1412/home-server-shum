# Design

## Context

Мотивация — `proposal.md`. Ограничения: Windows 10 Home, без прав администратора; из инструментов — только Node.js 24 и Git (restic/Kopia не установлены); один рабочий диск `C:` и USB-флешка ADATA (NTFS, метка `reserve`); дашборд уже читает `backup-status.json` (`system-status`). Процессы из Claude Desktop (MSIX) пишут в AppData виртуализированно — поэтому весь сервер живёт в `C:\FamilyServer` (ADR-0002).

## Goals / Non-Goals

**Goals:**
- Копия, которую можно проверить без запуска портала: обычные файлы + `manifest.json` с SHA-256.
- Отказ одного места (вынутая флешка) не мешает другому и сразу виден на дашборде.
- Восстановление физически не может испортить рабочие данные.

**Non-Goals:**
- Шифрование, копия вне дома, инкрементальные копии и дедупликация (данных — единицы МБ).
- Запуск копирования или восстановления из UI/API.

## Decisions

- **D1. Свой модуль на Node.js** (`server/src/backup/`: `spec`, `targets`, `sources`, `snapshot`, `retention`, `restore`, `status`, `run`) вместо robocopy/«Истории файлов» (нет проверки по хэшам и статуса) или restic/Kopia (не установлены; оставлены для копии вне дома). Подробно — ADR-0004.
- **D2. Источники собираются один раз** (данные, `.env`, `git bundle create --all` во временную папку, `tailscale serve status --json`, `system-info.json`), затем пишутся в каждое место; одно имя снимка (время UTC) во всех местах.
- **D3. `.partial` → перечитать и сверить SHA-256 + `git bundle verify` → `rename`.** Окончательное имя означает «проверено»; прерванная запись остаётся `.partial` и удаляется через 24 ч.
- **D4. Флешка по метке тома.** `label:reserve\FamilyServerBackups` разрешается через новый фиксированный read-only PowerShell-скрипт `volumes` (`Get-Volume`), без пользовательских аргументов; буква диска не важна, две одинаковые метки — ошибка.
- **D5. Статус** — атомарная запись `backup-status.json` в каталог данных; `lastSuccessAt` двигается только при успехе всех мест, `restoreTestedAt` — только при полном успехе `test-restore`. `server/src/system/backup.ts` строит из `targets` итог «основной диск — да, флешка «reserve» — нет» и причины.
- **D6. Восстановление** — только в новую/пустую папку вне рабочего каталога данных (проверка и по пути, и по реальному пути с учётом junction); замена данных — вручную при остановленном сервере.
- **D7. Git без shell:** `execFile` с фиксированными аргументами и таймаутом 5 мин; путь — `GIT_EXE`.
- **D8. Расписание** — задача планировщика текущего пользователя (`Interactive`, `Limited`, `StartWhenAvailable`, лимит 1 ч), вывод дописывается в `logs\backup.log`.
- **D9. Перенос из AppData:** каталог данных по умолчанию на Windows — `%SystemDrive%\FamilyServer\data\dashboard`; скрипты сначала ищут `C:\FamilyServer\tools\nodejs\node.exe`.

## Risks / Trade-offs

- [Копия на `C:` — тот же физический диск] → вторая копия на флешке; в документации и на дашборде это названо прямо.
- [Флешка в том же доме, копии не зашифрованы] → хранить флешку бережно, при потере — сменить пароли; зашифрованная копия вне дома — следующий шаг (решение владельца).
- [Флешку вынули] → это место завершается ошибкой, дашборд показывает «ошибка» и критическое предупреждение.
- [Задача не выполняется без входа в Windows] → `StartWhenAvailable` + статус «устарела» через 8 дней.
- [В `repo.bundle` только закоммиченный код] → незакоммиченные правки не защищены; коммитить вовремя.

## Migration Plan

1. Перенести Node.js и Git в `C:\FamilyServer\tools`, данные — в `C:\FamilyServer\data\dashboard`; задать права; обновить user PATH (прежний сохранён в `C:\Users\PC\family-server-backups\userpath-backup-2026-10-16.txt`); `.env`: `DASHBOARD_DATA_DIR`, `GIT_EXE`.
2. Перезапустить портал из Проводника; `scripts\backup.cmd`, `verify`, `test-restore`; `scripts\backup-schedule.cmd`.
3. Откат: `scripts\backup-schedule.cmd -Off`; копии и старые файлы в пакете Claude не удалялись.
