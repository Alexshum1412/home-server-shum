# Локальная модель «Оливии»

Статус на 20.10.2026: **установлена, работает под супервизором, проверена на этом ПК** (замеры ниже). Без модели «Оливия» продолжает работать на правилах — это запасной способ, он включается сам. Почему так — [ADR-0011](../decisions/0011-olivia-local-model.md).

## Что установлено

| Что | Откуда | Размер | Контроль |
|---|---|---|---|
| `llama-b11669-bin-win-cpu-x64.zip` — llama.cpp, сборка для процессора | github.com/ggml-org/llama.cpp, релиз `b11669` | 19 537 886 байт (около 19 МБ) | SHA-256 `37b3efcf…632b` закреплён в `scripts\components.json` |
| `qwen2.5-1.5b-instruct-q4_k_m.gguf` — модель | huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF | 1 117 320 736 байт (около 1,04 ГБ) | SHA-256 `6a1a2eb6…407e` закреплён там же |

**Откуда взята версия.** Проект llama.cpp публикует Windows-сборки только как предварительные релизы (около 15 в сутки, метка `bNNNN`). Выпуск, помеченный автором как стабильный, содержит один файл `nightly-tag.txt`, и в нём указана сборка `b11669` — её и закрепили. Раньше в документах была указана более новая сборка `b11717` (ежедневная); её заменили на ту, на которую указывает стабильный выпуск проекта.

**Что это доказывает и чего не доказывает.** Издатель не публикует отдельного файла с контрольной суммой; закреплённая сумма — та, что GitHub посчитал для загруженного файла (прочитана через API GitHub). Она подтверждает, что файл тот самый, что хранит GitHub, и что он не изменится незаметно при следующей установке. **Подлинность независимо она не доказывает.** Сумма, которую посчитали мы сами после скачивания, — тоже не доказательство подлинности. Данные семьи в эти загрузки не отправляются.

Модель Qwen2.5 лицензирована как Apache-2.0, llama.cpp — как MIT.

## Как это запускается (и чем защищено)

- Запускает и перезапускает после сбоя **супервизор** (программа `llama`), как Jellyfin. Модель появляется, только если есть `llama-server.exe`, файл модели и в `.env` задан `OLIVIA_LLM_URL`.
- Слушает **только `127.0.0.1:8081`**. Но на loopback достучится любая программа на ПК и любая страница, открытая в браузере на этом ПК, поэтому сервер запускается с **ключом доступа** (`--api-key-file`): случайное значение создаётся один раз, лежит в папке данных портала (`llama-api.key`, не в Git) и подставляется порталом в каждый запрос. Запрос без ключа получает отказ.
- Приоритет процесса — **«ниже обычного»**, потоков — 3 из 4 (`OLIVIA_LLM_THREADS`), контекст 2048, один запрос за раз. Так модель не отнимает ядро у Jellyfin и портала.
- Модель **только выбирает инструмент** из закрытого списка и слова запроса из самого вопроса. Данных семьи (названий фильмов, имён файлов, событий) она не получает; ссылку берёт код из сообщения человека, не модель. Подробности — ADR-0011.

## Установка (если нужно поставить заново)

```bash
scripts\ai-setup.cmd
```

Скрипт показывает файл, источник и размер и спрашивает «да». Размер и SHA-256 проверяются до распаковки; при несовпадении ничего не устанавливается. Прерванная загрузка продолжается (не начинается с нуля). Установит в `C:\FamilyServer\apps\llama` и `C:\FamilyServer\data\models`. Затем добавьте в `.env` (UTF-8 **без** BOM) строку:

```
OLIVIA_LLM_URL=http://127.0.0.1:8081/v1
```

и перезапустите программы:

```bash
scripts\restart.cmd
```

Проверка: `scripts\status.cmd` — строка «Языковая модель Оливии (llama.cpp): работает»; на странице «Сервер» программа `llama` в списке; в «Оливии» — «Языковая модель работает на этом компьютере».

## Замеры на этом ПК (20.10.2026)

Измерено скриптом `tests\live\olivia-model-bench.mjs`: он задаёт запущенной модели 20 фиксированных вопросов два раза подряд через тот же код выбора, что использует портал, и сравнивает выбор модели с ожидаемым и с выбором правил. Повторить: `node tests\live\olivia-model-bench.mjs --rounds 2` (модель должна быть запущена).

| Показатель | Результат |
|---|---|
| Выбор инструмента, 40 запросов | модель верно — **34 из 40**; правила без модели — 32 из 40 |
| Что не сработало у модели | 4 запроса: на «как сменить пароль» и «сколько будет два плюс два» модель выбрала «загрузку» без ссылки — код это отбросил и ответил правилами; ещё 2 — «как загрузить файл с телефона» принят за поиск файла (правила решают его сами, уверенно) |
| Время ответа | медиана **1,7 с**, 90-й процентиль 2,05 с |
| Первый запрос после простоя | около **8,5 с** (модель подгружается в память) |
| Память `llama-server.exe` | в покое Windows сжимает её до нескольких мегабайт; при ответах **около 1,06 ГБ** |
| Влияние на другие программы | отдельно не измерялось; защита — низкий приоритет и 3 потока |

**Как читать.** В «Оливии» правила идут первыми: понятные формулировки решаются мгновенно, модель подключается только для вопросов, где правила не уверены, а при ошибке модели ответ строится по правилам. Поэтому ошибка модели не приводит к неверному действию: худшее, что она может, — выбрать не тот инструмент из списка (ничего не меняющих действий для семьи в списке нет).

**Сбой, который наблюдался.** Однажды сборка завершилась аварийно (код 0xC0000374, повреждение кучи) на новой схеме ответа; на 80 запросах подряд это не повторилось. Супервизор перезапускает программу сам, «Оливия» на время отвечает по правилам. Если сбои повторятся, откат — убрать `OLIVIA_LLM_URL` (модель не запускается) или закрепить другую сборку.

## Настройки в `.env` (все необязательны)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OLIVIA_LLM_URL` | пусто (модели нет) | адрес **только на этом ПК** |
| `OLIVIA_LLM_MODEL` | `local` | подпись модели |
| `OLIVIA_LLM_TIMEOUT_SEC` | 90 | сколько ждать ответ |
| `OLIVIA_MODEL_FILE` | `C:\FamilyServer\data\models\qwen2.5-1.5b-instruct-q4_k_m.gguf` | файл модели |
| `OLIVIA_LLM_THREADS` | 3 | потоки процессора (1–16) |
| `OLIVIA_LLM_CONTEXT` | 2048 | длина контекста (512–8192) |
| `SUPERVISE_LLAMA` | включено | `0` — не запускать модель супервизором |

## Запуск, остановка, обновление, смена

- Статус/запуск/остановка: `scripts\service.cmd status|start|stop|restart llama` или кнопки на странице «Сервер» (только администратор).
- Обновить программу: смените версию, размер и SHA-256 в `scripts\components.json`, остановите `scripts\service.cmd stop llama` и запустите `powershell -ExecutionPolicy Bypass -File scripts\install-component.ps1 -Name llama -Reinstall` (прежняя папка переименуется в `llama.old-<дата>`, не удаляется). После обновления прогоните `tests\live\olivia-model-bench.mjs` и сравните с таблицей.
- Другая модель: положите `.gguf` в `C:\FamilyServer\data\models`, пропишите `OLIVIA_MODEL_FILE`, `service.cmd restart llama`. Для русского и JSON подходят Qwen2.5 1.5B/3B; модели больше 3B на этом ПК не рекомендуются (4 ядра, 16 ГБ).
- Выключить совсем: уберите `OLIVIA_LLM_URL` — модель не запускается, «Оливия» на правилах.

## Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| «Языковая модель не подключена» | `OLIVIA_LLM_URL` не задан | добавьте строку и перезапустите (`scripts\restart.cmd`) |
| «не отвечает» | модель ещё грузится (до минуты после запуска) или программа упала | `service.cmd status`; журнал `llama.err.log` в папке журналов (на странице «Сервер» — последние строки без секретов) |
| Программа `llama` не появляется | нет `llama-server.exe` или файла модели, либо `SUPERVISE_LLAMA=0` | проверьте пути выше |
| Ответы странные | модель маленькая | это ожидаемо: итоговый ответ всё равно собирается из фактов; можно взять 3B |
| В папке моделей лежит чужой файл | например `gemma-3-4b-it-Q4_K_M.gguf` (2,49 ГБ), происхождение которого неизвестно | портал его не использует; не удаляли и не запускали; решение — за владельцем |
