# Ранбук: резервное копирование и восстановление

**Статус: Implemented / Partial** (16.10.2026; семейные данные и Jellyfin — с 17.10.2026).

- **Implemented:** ежедневная копия в два места — основной диск и флешка «reserve»; каждая копия проверяется по SHA-256; пробное восстановление проходит; дашборд показывает реальный результат.
- **Partial:** копии вне дома нет; копии не зашифрованы; копия на основном диске лежит на том же физическом диске, что и данные. Подробно — в разделе «Ограничения».

Решение и альтернативы — [ADR-0004](../decisions/0004-backups.md). Код: `server/src/backup/`, CLI `server/src/cli/backup.ts`, обёртки `scripts\backup.cmd`, `scripts\backup-schedule.cmd`.

## Что входит в копию

Одна копия — папка `family-backup-YYYYMMDD-HHMMSS` (время в имени — UTC; по Москве на 3 часа больше):

| Путь в копии | Что | Обязательно |
|---|---|---|
| `data\` | файлы `*.json` и `audit*.jsonl` из верхнего уровня папки данных `C:\FamilyServer\data\dashboard`: `users.json` (хэши паролей scrypt), `logins.json`, `services.json`, `audit.jsonl` (+ ротация) — какие есть | да: без папки данных копия не создаётся |
| `config\.env` | настройки проекта (`BACKUP_EXTRA_FILES`; по умолчанию — `.env` проекта, если он есть) | нет |
| `repo.bundle` | вся история Git проекта (`git bundle create --all`) — только **закоммиченный** код | нет |
| `network\tailscale-serve.json` | `tailscale serve status --json` | нет |
| `system-info.json` | версия портала, Node.js, ОС, имя ПК | — |
| `family\files\…` | семейные файлы `C:\FamilyData\Files` — личные папки всех (`users\<логин>`, включая «Загрузки») и общие (`shared`) | да (с 17.10.2026) |
| `family\photos\…` | фото и видео `C:\FamilyData\Photos` + миниатюры | да (с 17.10.2026) |
| `family\home-video\…` | `C:\FamilyData\Media\Домашнее видео` — семейные видео незаменимы | да (с 17.10.2026) |
| `jellyfin\config\…`, `jellyfin\data\…` | настройки и база Jellyfin (пользователи, библиотеки, что досмотрено). Копируются при **остановленном** Jellyfin: супервизор останавливает его на секунды и сразу запускает | да (с 17.10.2026) |
| `manifest.json` | список файлов с размером и SHA-256 (у семейных — ещё время изменения), сведения о коде и сети | — |

**Не копируются:** `sessions.json` (после восстановления все входят заново), `backup-status.json`, папки `logs\` и `run\`, временные `*.tmp`. Если код, `.env` или настройки Tailscale не удалось сохранить, копия всё равно создаётся, а причина пишется в `manifest.json` и в журнал как «Замечание».

**Не копируются, и это сознательно:**
- фильмы, сериалы, мультфильмы и музыка из `C:\FamilyData\Media`: их можно найти снова, а по объёму они больше любого носителя для копий;
- корзины `.trash`, недокачанные загрузки (`.part`), временные файлы;
- картинки-метаданные Jellyfin, его кэш, логи и временные файлы перекодирования.

**Версии без лишнего места.** Неизменённые семейные файлы (тот же размер и время изменения) в новой копии становятся **жёсткими ссылками** на тот же файл предыдущей копии на том же носителе:
- место занимает только новое и изменённое;
- каждая копия остаётся полной: её можно проверить и восстановить отдельно, а удаление старой копии не портит новую;
- новые и изменённые файлы при записи сверяются по SHA-256;
- связанные файлы при ночной записи проверяются по размеру: это те же данные, уже проверенные раньше;
- полная перепроверка всех байт — `scripts\backup.cmd verify`.

**Секрет в копии.** В копию входит `jellyfin-api.json` — ключ API Jellyfin для супервизора. Если флешка потеряна:
1. В Jellyfin: «Панель управления» → «Ключи API» → удалить ключ «FamilyServer».
2. Удалить файл `C:\FamilyServer\data\dashboard\jellyfin-api.json`.
3. Выполнить `scripts\jellyfin-setup.cmd` — он создаст новый ключ.
4. Сменить пароли пользователей.

## Где хранятся копии

| Место | Путь | От чего защищает | От чего не защищает |
|---|---|---|---|
| основной диск | `C:\FamilyServer\backups` | случайное удаление и порча файлов | отказ диска (тот же физический диск) |
| флешка «reserve» | `<буква>:\FamilyServerBackups` на томе NTFS с меткой `reserve` (флешка ADATA, сейчас `D:`) | отказ основного диска | кража, пожар (флешка в том же ПК и доме) |
| GitHub (только код) | https://github.com/Alexshum1412/home-server-shum, ветка `main` (`BACKUP_GIT_PUSH=origin/main`) | потерю **кода и документации** при любой беде с ПК | **данные семьи туда не попадают** — их защищают только два места выше |

GitHub — необязательное место: если отправка не удалась (нет интернета, истёк вход в GitHub, на GitHub появились коммиты, которых нет на ПК), копирование всё равно успешно, а дашборд и журнал показывают «GitHub (код) — нет» и причину. Отправка только fast-forward — история на GitHub никогда не перезаписывается. Восстановить вход: в папке проекта выполнить `git push` и войти в открывшемся окне Git Credential Manager.

Флешка находится **по метке тома**, а не по букве: буква может смениться после переподключения. В каждом месте хранятся **14** последних копий (`BACKUP_KEEP`); более старые удаляются только после того, как новая копия записана и проверена. Незавершённые папки `*.partial` старше 24 часов тоже удаляются. Больше в папке копий ничего не трогается.

Настройки — в `.env` (образец: [.env.example](../../.env.example)): `BACKUP_TARGETS`, `BACKUP_KEEP`, `BACKUP_REPO_DIR`, `BACKUP_EXTRA_FILES`, `GIT_EXE`.

## Как обеспечивается целостность

1. Источники собираются один раз; во всех местах копия получает одно и то же имя.
2. Каждое место пишется независимо: папка `<имя>.partial` → файлы и `manifest.json` → файлы перечитываются с диска и сверяются по SHA-256, `repo.bundle` проверяется `git bundle verify` → только после этого папка переименовывается в окончательное имя. При любой ошибке `.partial` удаляется.
3. Перед записью проверяется свободное место (размер копии + 50 МБ запаса). Копии не пишутся в корень диска и в папку данных портала.
4. Результат записывается в `C:\FamilyServer\data\dashboard\backup-status.json` (`lastRunAt`, `lastResult`, `lastSuccessAt`, `restoreTestedAt`, `targets`, `warnings`). Запуск успешен, только если успешны **все** места.

## Команды

Из папки проекта `C:\Users\PC\Desktop\THE DASHBOARD` (права администратора не нужны):

| Что | Команда |
|---|---|
| Сделать копию сейчас (можно двойным щелчком) | `scripts\backup.cmd` |
| Список копий в каждом месте | `scripts\backup.cmd list` |
| Проверить свежие копии / конкретную | `scripts\backup.cmd verify` / `scripts\backup.cmd verify <папка-копии>` |
| Пробное восстановление свежих копий во временную папку (записывает `restoreTestedAt`) | `scripts\backup.cmd test-restore` |
| Восстановить копию в новую пустую папку | `scripts\backup.cmd restore <папка-копии> --to <пустая папка> [--no-repo]` |
| Удалить копии сверх `BACKUP_KEEP` | `scripts\backup.cmd prune` |
| Справка (с текущими местами хранения) | `scripts\backup.cmd --help` |
| Включить / выключить ежедневную копию | `scripts\backup-schedule.cmd` / `scripts\backup-schedule.cmd -Off` |

Код завершения: `0` — всё в порядке, `1` — ошибка (строки «ОШИБКА» в выводе), `2` — неверная команда.

## Расписание

Задача планировщика **«FamilyServerBackup»** (текущего пользователя): каждый день в **03:30**; если ПК в это время был выключен — при первой возможности; выполняется, **только пока пользователь вошёл в Windows** (пароль в планировщике не хранится); лимит — 1 час. Журнал: `C:\FamilyServer\data\dashboard\logs\backup.log`.

## Что показывает дашборд

«Состояние системы» → резервное копирование:

| Состояние | Когда | Текст / предупреждение |
|---|---|---|
| в порядке | последний запуск успешен во всех местах | «Последняя копия … : основной диск — да, флешка «reserve» — да» |
| ошибка | хотя бы одно место не записано | какое место и почему + критическое предупреждение «Резервное копирование не удалось» для всех |
| устарела | успешной копии нет больше 8 дней | предупреждение «Резервная копия устарела» |
| не настроено | нет `backup-status.json` (копирование ещё не запускалось) | предупреждение «Резервные копии не настроены» |
| нет данных | `backup-status.json` повреждён или не читается | «Файл состояния резервного копирования повреждён или не читается» |

Пока не пройден `test-restore`, к тексту добавляется «Восстановление из копии ещё не проверялось».

## Восстановление данных портала

Восстановление **никогда не пишет в рабочую папку данных** — сначала копия разворачивается в новую пустую папку, затем файлы заменяются вручную при остановленном сервере.

1. Выбрать копию: `scripts\backup.cmd list`.
2. Развернуть её в новую пустую папку, например в `C:\FamilyServer\data\` (там права только у PC, SYSTEM и администраторов):
   ```bat
   scripts\backup.cmd restore D:\FamilyServerBackups\family-backup-YYYYMMDD-HHMMSS --to C:\FamilyServer\data\restore-YYYYMMDD
   ```
   Команда сначала проверяет копию, после записи сверяет каждый файл по SHA-256 и (без `--no-repo`) клонирует код в `<папка>\repo`.
3. Остановить портал: `scripts\stop.cmd`.
4. Заменить файлы в `C:\FamilyServer\data\dashboard` файлами из `<папка>\data\*`.
5. Запустить портал: `scripts\start.cmd` и проверить вход. Сессии не восстанавливаются — все входят заново.
6. После проверки удалить папку восстановления (в ней хэши паролей).

### Восстановление семейных файлов и фото

Развернуть копию в новую папку (шаг 2 выше) и скопировать нужное обратно:

| Что | Откуда (в папке восстановления) | Куда |
|---|---|---|
| один файл или папка | `family\files\shared\…`, `family\files\users\<логин>\…` | `C:\FamilyData\Files\…` на то же место |
| фото и видео | `family\photos\…` | `C:\FamilyData\Photos\…` |
| домашнее видео | `family\home-video\…` | `C:\FamilyData\Media\Домашнее видео\…` |

Портал останавливать не нужно: файлы появятся в «Файлах» и «Фото» сразу.

Проверено 17.10.2026:
1. Тестовый файл в общем пространстве попал в копию; затем его «удалили».
2. Его восстановили с флешки (`backup.cmd restore D:\FamilyServerBackups\family-backup-20261017-030909 --to … --no-repo`).
3. SHA-256 совпал с исходным, файл вернулся на место.

### Восстановление Jellyfin

1. `scripts\stop.cmd` — останавливаются портал и Jellyfin.
2. Переименовать `C:\FamilyServer\data\jellyfin\config` и `…\data` в `*.old`.
3. Скопировать `jellyfin\config` и `jellyfin\data` из папки восстановления в `C:\FamilyServer\data\jellyfin\`.
4. `scripts\start.cmd`. Картинки-обложки Jellyfin скачает заново сам.

Остальное из копии:

- **Код:** `git clone <папка>\repo.bundle <новая папка>` или готовая папка `<папка>\repo`.
- **Настройки:** `<папка>\config\.env` → скопировать в папку проекта.
- **Tailscale Serve:** `<папка>\network\tailscale-serve.json` — для сверки; включается заново командой `scripts\serve-tailnet.cmd`.

## Если флешка не подключена или копия не удалась

| Симптом | Что делать |
|---|---|
| В журнале или выводе: «ОШИБКА флешка «reserve»: Флешка «reserve» не подключена»; на дашборде — «ошибка» | вставить флешку (буква не важна) и запустить `scripts\backup.cmd`; копия на основной диск при этом уже сделана |
| «Найдено несколько дисков с меткой «reserve»» | оставить метку `reserve` только у одного тома |
| «Недостаточно места» | `scripts\backup.cmd prune`, уменьшить `BACKUP_KEEP` или взять флешку больше |
| «Git не найден» (замечание, код не сохранён) | проверить `GIT_EXE` в `.env` (`C:\FamilyServer\tools\git\cmd\git.exe`) |
| Задача не выполнилась ночью | ПК был выключен или не был выполнен вход в Windows — задача запустится после входа; можно запустить `scripts\backup.cmd` вручную |
| Новая флешка вместо старой | владелец вручную форматирует её в NTFS с меткой `reserve` (форматирование стирает всё на ней; устройство `ST_M13FQBL` не трогать), затем `scripts\backup.cmd` и `scripts\backup.cmd test-restore` |

Подробности ошибки — в `C:\FamilyServer\data\dashboard\logs\backup.log` и в выводе `scripts\backup.cmd verify`.

## Ограничения

- Копия на основном диске защищает только от удаления и порчи файлов, но не от отказа диска.
- Флешка — отдельное устройство, но в том же ПК и доме: от кражи и пожара не защищает. Вынутая флешка → это место завершается ошибкой, дашборд показывает «ошибка».
- Копии **не зашифрованы**. Пароли хранятся как хэши scrypt, но флешку нужно хранить бережно; если она потеряна — сменить пароли всех пользователей (`scripts\user.cmd passwd <логин>`).
- Копии вне дома (зашифрованной) пока нет.
- Задача выполняется только при выполненном входе в Windows.

## Какое оборудование нужно (честно)

Сейчас семейных данных мало: копия занимает 13 МБ. Флешка «reserve» — всего 14,9 ГБ. Когда семейные файлы, фото и домашнее видео перерастут её, копия на флешку завершится **ошибкой** «Недостаточно места». Дашборд это покажет; копия на C: при этом продолжится. Для настоящей защиты от отказа единственного диска нужны:

1. **Внешний USB-диск** не меньше объёма семейных данных × 2. Практично — 2 ТБ:
   - отформатировать владельцем в NTFS с меткой `reserve` вместо флешки (или `reserve2` и добавить в `BACKUP_TARGETS`);
   - хранить подключённым к ПК или подключать хотя бы раз в неделю.
2. **Второй внутренний диск** вместо неисправного `ST_M13FQBL` — по решению владельца (`docs/runbooks/second-disk.md`). Его тоже можно добавить в `BACKUP_TARGETS`.
3. **Копия вне дома** (кража, пожар) — см. следующий раздел. Только с шифрованием.

## Как добавить копию вне дома (позже, по решению владельца)

1. Владелец выбирает место (второй дом, ПК родственника, облако) и где хранить ключ шифрования — отдельно от копий.
2. Незашифрованные копии допустимы только на носителях, которые владелец контролирует физически: ещё одно место можно добавить в `BACKUP_TARGETS` через `;` — полный путь, сетевая папка `\\компьютер\папка\подпапка` или `label:<метка>\<папка>` (например, вторая флешка, которая хранится вне дома и периодически приносится для копии).
3. Для облака или чужого компьютера нужно шифрование до отправки (кандидаты — restic или Kopia; сейчас **не установлены**, выбор — после проверки официальной документации).
4. Семейные данные **никогда** не отправляются в GitHub: там только код проекта.
5. После добавления: `scripts\backup.cmd`, `scripts\backup.cmd verify`, `scripts\backup.cmd test-restore`; обновить этот ранбук и `docs/roadmap.md`.
