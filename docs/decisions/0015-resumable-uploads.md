# ADR-0015: загрузка файлов и фото с докачкой, пропуском повторов и вырезанием метаданных

**Статус:** принято и реализовано 19–20.10.2026. Уточняет [ADR-0007](0007-files-and-photos.md) (встроенное хранилище остаётся).

## Контекст

Семья загружает фото с телефонов пачками по десятку и больше. Хрупкая загрузка «файл за файлом одним запросом» плохо переносит обрыв мобильной сети: после обрыва всё начиналось заново, одинаковые снимки загружались по второму разу, в JPEG уходили координаты съёмки и данные о камере, а удалённое пропадало без возврата. По заданию владельца нужны: выбор многих файлов, общий прогресс, повтор, докачка, пропуск точных повторов, альбомы, вырезание EXIF/GPS по желанию, корзина с возвратом, квота, перемещение и просмотр. При этом: без новых больших компонентов, без облаков, без удаления данных и с защитой путей.

## Решение

1. **Передача кусками (возобновляемая загрузка).** Протокол из пяти запросов (`session` → `PUT ?offset=` → `status` → `finish` → `cancel`); сервер хранит частичные данные в скрытой папке пространства и при расхождении позиции отвечает 409 с настоящей позицией. Файл появляется на месте **только** на `finish` и никогда не заменяет существующий (первое свободное имя). Малые файлы (до 8 МиБ) идут прежним одним запросом. Протокол свой, а не tus/другая библиотека: нужен небольшой, проверяемый и понятный набор правил, который целиком проходит через уже работающие проверки (программы, размер, место, квота).
2. **Пропуск точных повторов по SHA-256.** Браузер считает отпечатки, сервер хранит индекс по пространствам и обновляет его в фоне. Только точные совпадения; перекодированные и похожие не считаются. Пользователь всегда может загрузить повторы.
3. **Вырезание метаданных из JPEG** при загрузке по умолчанию (оставляются изображение, цветовой профиль и поворот); остальные форматы **не изменяются**, и интерфейс говорит об этом прямо. Выбор не навязывается: галочка снимается.
4. **Альбомы — папки** `Альбомы\<название>`: попадают в копии, поиск и «Файлы» без отдельной базы.
5. **Корзина без окончательного удаления.** Удалённое переносится в `.trash` с индексом имени и места (в `.index`), возвращается кнопкой; очистка — только администратором на сервере. Портал ничего не стирает насовсем (правило проекта).
6. **Квота** на личное пространство (`USER_QUOTA_GB`), по умолчанию выключена; предупреждение с 90 %, отказ при 100 %.
7. **Просмотр** только безопасных типов и только с запретом на выполнение кода (`sandbox` и `default-src 'none'`); HTML и SVG только скачиваются.

## Что отвергнуто

- **tus, S3-совместимые загрузки, WebDAV, Nextcloud/Immich/PhotoPrism** — новые большие компоненты, часть требует Docker/Linux (см. ADR-0007); для текущего размера семьи избыточно.
- **Фоновое автокопирование фото** — не просили; требует приложения на телефоне и права на фоновый доступ.
- **Сравнение «похожих» фото (перцептивные хэши)** — ложные срабатывания удаляют не те снимки; пропуск только точных копий безопаснее.
- **Автоматическое окончательное удаление корзины и версий файла** — противоречит правилу «не удалять данные»; вместо истории версий — «копия с номером» при совпадении имён.

## Последствия

- Файл при обрыве докачивается; один и тот же файл не ляжет дважды без желания человека; координаты из JPEG не уходят в семейную галерею по умолчанию.
- Частичные данные занимают место на диске, пока передача не закончена или не прошли сутки.
- Индекс отпечатков надо построить для старых фото (идёт в фоне после запуска, нагрузка низкая; пока не закончен, панель предупреждает).
- Honest limits: HEIC и видео сохраняют свои метаданные; «версий файла» как отдельной истории нет; настоящий телефон не проверялся.
