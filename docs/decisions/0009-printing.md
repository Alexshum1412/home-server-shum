# ADR-0009: Печать из портала — прямой IPP на принтер, PDF и JPEG, без обработки файлов на сервере

**Статус:** принято, реализовано 17.10.2026.

## Контекст

Этап P7 ТЗ: настоящая печать из портала, в том числе из другой страны.

Требования:
- доступ только разрешённым пользователям;
- лимит размера и проверка типа файла;
- корректная обработка ошибочных документов;
- загруженное содержимое никогда не исполняется;
- журнал результата;
- никаких Linux/CUPS и тяжёлых сред.

Принтер — HP Color LaserJet MFP M283fdw. Исследование 17.10.2026 только на чтение, отчёт workflow «printer-ipp-recon»:
- в сети `192.168.1.139` (mDNS `NPID6ECE2.local`);
- IPP 1.1/2.0, `ipps` на 443;
- форматы: `application/pdf`, `image/jpeg`, PCLm, URF, PostScript, PCL;
- двусторонняя печать; режимы цвета `auto/monochrome/color`; копии 1–999;
- **уровни тонера по IPP не сообщаются** (`marker-levels = -2`).

## Варианты

| Вариант | Минусы |
|---|---|
| Печать через Windows: открыть файл программой с `-Verb Print` | сервер открывает чужой документ программой просмотра — это и есть «исполнение» загруженного содержимого; нужна программа для PDF; окна в сеансе S4U не работают |
| CUPS / виртуальная машина | запрещено ТЗ («не устанавливай Linux/CUPS автоматически») |
| **Прямой IPP на принтер** (выбрано) | только PDF и JPEG (Word и Excel — сохранить как PDF); нужен адрес принтера в `.env` |

## Решение

- **Клиент.** `server/src/print/ipp.ts` — свой минимальный IPP-клиент без зависимостей, с тестами.
- **Транспорт.** `ipps` (TLS к самоподписанному сертификату принтера): документы семьи не идут по домашней сети открытым текстом.
  - Адрес принтера задаёт владелец: `PRINTER_IPP_URL=https://192.168.1.139/ipp/print` в `.env`. Из запроса адрес не берётся никогда, поэтому SSRF здесь нет.
  - IP, а не имя `NPID6ECE2.local`: разрешение mDNS-имени на этом ПК занимает 2–11 с.
- **Поток:**
  1. Файл загружается в `C:\FamilyServer\data\dashboard\print-spool` с лимитом (`PRINT_MAX_MB`, 30 МБ).
  2. Тип определяется по содержимому: `%PDF-` или JPEG. Остальное, включая программы и HTML, получает 415.
  3. Принтер проверяет задание (`Validate-Job` — ничего не печатается).
  4. Пользователь подтверждает (`{confirm: true}`).
  5. `Print-Job`; затем опрос `Get-Job-Attributes` до «напечатано / прервано / отменено».
  6. Отмена — `Cancel-Job`. Неподтверждённое задание через час устаревает.
  7. Файл из спула удаляется, как только задание закрыто.
- **Найденная особенность HP M283.** Если документ в `Print-Job` передан с заголовком `Content-Length`, прошивка **сразу прерывает задание** (`aborted-by-system`, 0 страниц) — так было с PDF и с JPEG, по IPP и по IPPS. CUPS и Windows передают документ блоками (`Transfer-Encoding: chunked`), и так печать проходит. Портал тоже отправляет документ блоками (тест `print.test.ts` → «IPP transport»).
- **Сервер файл не открывает:** не рендерит, не конвертирует, не запускает. Байты передаются принтеру как есть, а разбирает их сам принтер.
- **Права.** Право `print` выдаётся командой `scripts\user.cmd allow <логин> print`; у администраторов оно есть всегда. Каждый видит свои задания, администратор — все.
- **Журнал.** `print.submit`, `print.cancel`, `print.fail` пишутся с форматом, размером и числом копий, **без имени файла**: имя документа бывает личным.
- **Состояние принтера** узнаётся в фоне, раз в 30 с. Страница никогда не ждёт принтер: пока он не ответил, показывается «Проверяем».
- **Тонер.** Показывается только то, что сообщает сам принтер. Сейчас он уровень не сообщает, и портал так и пишет — без угаданных процентов.

## Проверено 17.10.2026

| Проверка | Результат |
|---|---|
| `print.test.ts` (8) | только PDF/JPEG по содержимому; Validate → подтверждение → Print-Job (документ передан байт в байт) → опрос до «напечатано», спул очищен; журнал без имени файла; формат, программа, превышение размера, отказ принтера → ошибка, спул пуст; права, чужие задания не видны, отмена → `Cancel-Job`; тонер −2 → «нет данных», 55 → 55 %; принтер выключен → «недоступен»; печать не настроена → 503; документ передаётся блоками; медленный принтер не задерживает страницу |
| e2e `print.spec.ts` (2) | без настроенного принтера — честное сообщение и 503; у члена семьи без права — пояснение и 403 |
| Реальная печать | после исправления передачи блоками — через интерфейс портала (Chrome, ширина 390): PDF → «Принтер проверил задание» → «Напечатать» → «Напечатано». Всего во время отладки напечатано 3 пробных листа: Windows, контрольный IPP, портал |

## Ограничения

- Word, Excel и другие форматы нужно заранее сохранить как PDF. Портал их не конвертирует — это сознательная мера безопасности.
- Если IP принтера сменится (DHCP), страница покажет «Не отвечает». Нужно закрепить адрес в роутере или исправить `PRINTER_IPP_URL` (`docs/runbooks/printing.md`).
- Из другой страны лист печатается дома: забрать его должен кто-то из домашних.
