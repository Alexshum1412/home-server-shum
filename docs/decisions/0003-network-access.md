# ADR-0003. Сетевой доступ к порталу

- **Статус:** принято · 16.10.2026

## Контекст

Родственники за границей, Tailscale 1.104.1 уже работает (`server-home.tail89d77e.ts.net`, HTTPS-сертификаты в tailnet разрешены, Serve не был настроен). Windows 10 без текущих обновлений безопасности. Нужны один адрес/иконка, HTTPS для PWA и никакого публичного доступа.

## Решение

- Сервер слушает **только `127.0.0.1:8070`**.
- **Главный адрес:** `https://server-home.tail89d77e.ts.net` — Tailscale Serve (`tailscale serve --bg --https=443 http://127.0.0.1:8070`), доступен только устройствам tailnet, с валидным сертификатом → PWA устанавливается на домашний экран.
- **Локально на ПК:** `http://127.0.0.1:8070`.
- **LAN-резерв** (при отказе интернета дома) — **не включён**: требует правила Windows Firewall (права администратора, изменение настроек безопасности). Подготовлена точная инструкция в `docs/runbooks/network.md`; включается только решением пользователя. В LAN портал будет обычным HTTP без установки PWA.
- Funnel, проброс портов роутера, изменение ACL/DNS Tailscale — **не используются**.

## Альтернативы

- Split-DNS с одним именем для LAN и tailnet — сложнее и хрупче на первом этапе.
- Привязка сервера к `0.0.0.0` — открыла бы порт и на интерфейсе стороннего VPN (профиль Public); отклонено.
- Доверять заголовкам `Tailscale-User-Login` вместо пароля — удобно, но ослабляет защиту при утере устройства; отложено как опция (только с loopback, только при явном включении).

## Последствия

- Удалённый доступ работает, пока ПК включён, пользователь вошёл в Windows (или Tailscale в режиме unattended) и дома есть интернет.
- Имя узла видно в публичных журналах Certificate Transparency (это не даёт доступа).
