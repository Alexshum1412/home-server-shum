# ADR-0007: Семейные файлы и фото — встроенный сервис портала вместо Nextcloud и Immich

**Статус:** принято, реализовано 17.10.2026.

## Контекст

Этап P4 ТЗ:
- личные файлы каждого и общие семейные документы;
- загрузка через веб, просмотр и скачивание;
- разграничение ролей, понятная структура папок;
- фото и видео с телефонов;
- никто не видит чужие личные файлы без разрешения.

ТЗ требует сначала проверить Nextcloud и Immich и не запускать их вслепую.

Ресурсы ПК:
- i5-6400 (4 ядра), 16 ГБ ОЗУ;
- уже работают Windows с обычной работой семьи, портал (~100 МБ) и Jellyfin (~200 МБ);
- один исправный HDD на 2 ТБ (NTFS);
- нет Docker, WSL2 и Hyper-V.

## Проверка вариантов (официальные требования, прочитаны 17.10.2026)

| | Nextcloud | Immich | Встроенный сервис портала |
|---|---|---|---|
| ОС сервера | только Linux (Ubuntu, RHEL, Debian, SUSE, CentOS Stream, Alpine); Windows — **только как клиент** | «Linux 64-bit»; Windows — через Docker Desktop/WSL2, «strongly discouraged»; база **не работает на NTFS** | Windows, без новых компонентов |
| Нужно установить | PHP 8.3–8.5, MariaDB/PostgreSQL, Apache/nginx + PHP-FPM | Docker + Compose, PostgreSQL, Redis, ML-контейнер | ничего |
| Память | ≥ 512 МБ на процесс PHP | **минимум 6 ГБ, рекомендовано 8 ГБ** | ~0 сверх портала |
| Изменения системы | Linux-сервер или ВМ | включить WSL2/Hyper-V (компоненты Windows, перезагрузка, BIOS-виртуализация) | нет |
| Мобильные приложения и автокопирование | есть (iOS/Android) | есть (фоновая выгрузка) | нет: загрузка через браузер |
| Вход и права | свои учётные записи | свои учётные записи | общий вход портала, роли и личные папки |
| Резервное копирование | база + data + config | база PostgreSQL + библиотека | обычные файлы на диске |

**Вывод.**
- Nextcloud на Windows-сервере не поддерживается вовсе.
- Immich требует Docker/WSL2 — а включение компонентов Windows ТЗ запрещает. Кроме того, ему нужно 6–8 ГБ ОЗУ из 16, общих с Windows, Jellyfin и семьёй, и не-NTFS-хранилище для базы.
- Ни то ни другое безопасно и честно на этом ПК не запускается.
- Выбран минимальный вариант без новых компонентов: файлы и фото — встроенная часть портала.

## Решение

- **Хранение.** Только обычные файлы на исправном диске, права NTFS — PC, SYSTEM, администраторы:
  - `C:\FamilyData\Files\users\<логин>` — личные файлы, включая «Загрузки» из P3;
  - `C:\FamilyData\Files\shared` — общие;
  - `C:\FamilyData\Photos\users\<логин>\ГГГГ-ММ`, `…\shared\ГГГГ-ММ` — фото и видео по месяцам;
  - `…\.trash\…` — корзина;
  - `C:\FamilyData\Photos\.thumbs\…` — миниатюры.
- **Приватность.**
  - Личное пространство вычисляется из сессии, а не из запроса. Никакой параметр не открывает чужую личную папку — даже администратору через портал. Администратор Windows, разумеется, видит диск: это ограничение сервера, не портала.
  - В журнале аудита действия в личном пространстве записываются без имён файлов.
- **Пути.**
  - Каждый путь проверяется по частям: зарезервированные имена Windows, `:`-потоки, `..`, хвостовые точки.
  - Затем через `realpath`: ссылки и junction наружу дают 403. Символические ссылки в списках не показываются.
- **Загрузка.**
  - `PUT` с сырым телом и заголовком `X-Upload: 1`: это исключение из правила «только JSON», а Origin и Sec-Fetch-Site проверяются как обычно.
  - Запись идёт потоком во временный скрытый файл и переименовывается только целиком.
  - Проверяются: заявленный размер, лимит (`UPLOAD_MAX_FILE_GB`, 20 ГБ), запас места (`MIN_FREE_GB`).
  - Программы отклоняются по имени и по содержимому (`MZ`).
  - В «Фото» принимаются только настоящие изображения и видео: определение по первым байтам — JPEG, PNG, GIF, WebP, HEIC/AVIF, MP4/MOV, WebM.
- **Выдача.**
  - По умолчанию — как скачивание.
  - Встроенный просмотр — только безопасных типов (изображения, видео, аудио, PDF, текст) и только с `Content-Security-Policy: sandbox`. HTML и SVG никогда не показываются в браузере.
  - Range-запросы поддерживаются: без них видео на iPhone не перематывается.
- **Удаление.** Только в корзину. Окончательно портал ничего не удаляет; корзину чистит администратор на ПК.
- **Миниатюры.** Их делает браузер, который загружает фото (canvas → JPEG до 360 px). Сервер ничего не декодирует, а значит, у него нет уязвимых декодеров изображений.
  - Если браузер не умеет формат (HEIC в Chrome), показывается значок.
  - Видео без миниатюры: blob-адреса запрещены нашей CSP.

## Честные ограничения

- **Это не фоновое резервное копирование телефона.** Фото добавляются вручную: «Фото» → «Добавить фото и видео» (на iPhone — выбор из «Фото»; Safari при выборе обычно отдаёт JPEG).
  - Автоматическую выгрузку по ночам портал не делает.
  - Проверено в Chrome на ПК (e2e). На реальном iPhone и Android — ручная проверка владельца.
- Нет поиска по лицам и местам, нет альбомов, кроме «Мои» и «Общие», нет совместного редактирования документов.
- Большие файлы с телефона уходят одним запросом: при обрыве связи загрузку надо повторить.

## Если позже понадобится Immich

Возможно на отдельном Linux-ПК или после решения владельца о WSL2:
- ≥ 8 ГБ свободной ОЗУ;
- SSD для базы.

Файлы из `C:\FamilyData\Photos` можно подключить к Immich как внешнюю библиотеку без переноса.
