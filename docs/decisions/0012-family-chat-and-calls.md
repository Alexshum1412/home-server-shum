# ADR-0012: семейный чат и звонки — внутри портала, без сторонних сервисов

**Статус:** принято 18.10.2026. Реализовано; проверено на одном ПК двумя окнами Chrome (см. «Что проверено»).

## Контекст

Владельцу нужен единый семейный центр: личные и групповые чаты, файлы и картинки в сообщениях, уведомления, голосовые и видеозвонки. Данные семьи не должны уходить в чужие облака; приложений для телефонов не делаем (PWA).

## Решение

**Чат.**
- Хранение в `C:\FamilyData\Chat` (журнал сообщений и вложения), попадает в резервную копию.
- Личные и групповые разговоры. Разговор **невидим для не-участников — для сервера они получают 404, включая администратора**. Администратор не читает чужую переписку и не видит чужих паролей.
- Вложения (картинки, файлы) до `CHAT_MAX_FILE_MB` (200 МБ), проверка свободного места; программы (.exe, .bat, .ps1 …) не принимаются.
- Доставка в реальном времени: **SSE** (`/api/events`, сервер → страница) + обычные POST. SSE проходит через Tailscale Serve и туннель как обычный HTTP; запасной путь — повторный опрос при возврате на вкладку.
- Прочитано / доставлено, непрочитанные счётчики, предпросмотр сообщения в уведомлении — по выбору человека.

**Уведомления** (центр уведомлений в портале + Web Push).
- Виды: новое сообщение, входящий звонок, загрузка завершена или не удалась, неудачная копия, мало места, критический сервис, печать завершена. Человек сам выбирает, что получать.
- Web Push написан на `node:crypto` (RFC 8291/8188, VAPID), проверен на векторе из RFC. Адреса push-служб — по списку разрешённых.
- **Ограничения, о которых нельзя молчать:** push на iPhone работает только у портала, добавленного «На экран Домой» (iOS 16.4+); в Safari-вкладке — нет. Если у браузера нет push, остаётся счётчик на значке и список в портале при открытии. Одинаковости на всех устройствах не обещаем.

**Звонки.**
- WebRTC, **сетка до 4 участников** (каждый с каждым), аудио и видео. Сервер портала только передаёт сигналы (предложение/ответ/ICE) — по SSE и POST; медиа через него не идёт.
- Роли фиксированы: тот, кто вошёл позже, делает предложение (нет «встречных» предложений).
- Звонок звонит ограниченное время, пропущенный звонок попадает в чат.
- **STUN/TURN.** Для двух устройств в разных сетях нужен хотя бы STUN, за строгим NAT (мобильные сети, часть домашних роутеров) — TURN. Настройки: `CALLS_STUN_URLS`, `CALLS_TURN_URLS`, `CALLS_TURN_SECRET` (временные логины TURN по схеме HMAC, срок `CALLS_TURN_TTL_SEC`). **Из коробки не настроено**: публичный STUN не включён без решения владельца (он раскрывает внешний адрес устройства стороннему серверу), TURN нужно поставить (например, coturn) — см. [runbooks/chat-and-calls.md](../runbooks/chat-and-calls.md).
- Звонки через Tailscale между устройствами одной tailnet обычно соединяются напрямую, без TURN.

## Что проверено (и что нет)

| Проверка | Результат |
|---|---|
| Автотесты чата, прав, 404 для не-участников, вложений | пройдены |
| Автотесты менеджера звонков (вызов, ответ, отказ, занято, пропущенный, лимит участников) | пройдены |
| e2e в Chrome: два окна, два пользователя, **настоящее WebRTC-соединение** с тестовыми устройствами камеры и микрофона на одном ПК | пройдено |
| Два **разных** устройства в разных сетях (телефон на мобильной связи ↔ ПК/ноутбук) | **не проверено, требует владельца**; TURN не настроен |
| Web Push на настоящем телефоне | **не проверено**; криптография проверена по RFC |

## Альтернативы

- Matrix/Element, Mattermost, Jitsi — готовые, но тяжёлые отдельные серверы (Docker/Java), свои учётные записи; противоречит «одна учётная запись, один портал, ничего лишнего».
- Облачные мессенджеры — семейные данные у третьей стороны; отклонено.
- SFU для групп больше 4 — избыточно для семьи.

## Последствия

- Звонок на мобильной связи без TURN может не соединиться. Это не баг, а свойство сети; интерфейс говорит об этом простыми словами.
- Группа больше 4 человек в одном звонке не поддерживается.
