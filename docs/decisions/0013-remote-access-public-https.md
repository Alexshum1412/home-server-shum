# ADR-0013: удалённый доступ — Tailscale основной, защищённый HTTPS-туннель дополнительный (только обычные функции)

**Статус:** принято 18.10.2026. Код политики каналов реализован и проверен автотестами; **сам туннель не настроен** (нужна учётная запись и домен владельца) — статус «Требует внешней настройки».

## Контекст

Окончательное решение владельца: основной путь — Tailscale (ADR-0003). Дополнительно допускается защищённый HTTPS-доступ (Cloudflare Tunnel или аналог) **только для обычных семейных функций**. Админ-панели и опасные операции публично недоступны. Туннель — не замена входу в портал. Секреты — вне репозитория.

## Решение

1. **Два канала.** Запрос приходит либо по частному пути (Tailscale, домашняя сеть, сам ПК), либо по публичному — через имя из `PUBLIC_HTTPS_URL`. Канал определяется по адресу, на который пришёл запрос (`Host` или `X-Forwarded-Host` от локального прокси), а также по заголовкам края Cloudflare (`cf-ray` и др.). Заголовок может только **ужесточить** запрос, поэтому подделка из tailnet ничего не открывает.
2. **Список, а не запрет.** На публичном канале доступны только маршруты из явного списка (`server/src/lib/channel.ts`): вход/выход/смена пароля/свои устройства, чат, звонки, уведомления, файлы и фото, каталог кинотеатра (без потока), календарь, заметки, вопрос «Оливии», просмотр загрузок и состояния. Всё остальное — 403 `channel_restricted`, в том числе будущие маршруты, пока их не внесут в список сознательно.
3. **Закрыто на публичном канале:** весь `/api/admin/*`; управление сервисами и «Оливия»-действия; запуск, пауза, отмена загрузок и торрентов; проверка ссылок (SSRF-поверхность); печать; восстановление; экспорт диагностики; поток фильмов (по умолчанию — условия бесплатного плана Cloudflare не предназначены для видео; включается `PUBLIC_ALLOW_MEDIA_STREAM=1` осознанно).
4. **Администратор не входит через публичный адрес** (`PUBLIC_ALLOW_ADMIN_LOGIN=0` по умолчанию): вход с верным паролем отклоняется кодом `admin_not_public`. Ответ на неверный пароль не отличается от обычного — посторонний ничего не узнаёт об учётной записи.
5. **Отдельные счётчики попыток входа** для публичного канала: шум из интернета не блокирует семью, входящую из дома или по Tailscale.
6. **Куки всегда `Secure`** на публичном канале; `SameSite=Strict`, проверка `Origin` и `Host` действуют как везде. Адрес из `PUBLIC_HTTPS_URL` добавлен в список разрешённых имён; неверно настроенный туннель (чужое имя в `Host`) получает 421 — работает «закрыто по умолчанию».
7. **Интерфейс** показывает баннер «Вы вошли через внешний адрес…» и убирает недоступное (запуск загрузок).

## Что делает владелец (не сделано, потому что нужны ваши аккаунт и домен)

Подробно — [runbooks/public-https.md](../runbooks/public-https.md): аккаунт Cloudflare, домен, `cloudflared`, имя в `PUBLIC_HTTPS_URL`, **обязательно Cloudflare Access** (вход по одноразовому коду на почты семьи) перед входом в портал: это второй замок снаружи, а не вместо пароля.

## Что сознательно не делается

Funnel Tailscale, проброс портов роутера, изменения ACL/DNS/маршрутов Tailscale, публикация админки, учётные данные туннеля в Git.

## Таблица поведения

| Ситуация | Tailscale (основной) | Туннель (дополнительный) |
|---|---|---|
| Чат, файлы, фото, календарь, Оливия | да | да |
| Звонки | да, напрямую | сигналы да; медиа — через STUN/TURN (см. ADR-0012) |
| Фильмы | поток через Jellyfin и портал | карточки да, поток по умолчанию нет |
| Загрузки и торренты | да | только просмотр |
| Администрирование, сервисы, диагностика, печать | да | нет |
| Вход администратора | да | нет |
| Что нужно для работы | Tailscale на устройстве | интернет и туннель на ПК; ничего на устройстве |
| Если ПК/интернет дома выключены | не работает ничем | не работает ничем |
