# ADR-0002. Где и как хранятся данные

- **Статус:** принято · 16.10.2026

## Контекст

Один рабочий диск `C:` (2 ТБ, ~1,8 ТБ свободно); второе устройство определяется как неисправное (`ST_M13FQBL`, 3,9 ГБ). Дашборду нужно хранить немного своих данных: пользователи, сессии, журнал аудита, список сервисов. Медиатека и фото будут у отдельных сервисов.

## Решение

1. **Код** — только в `C:\Users\PC\Desktop\THE DASHBOARD` (Git).
2. **Данные дашборда** — в `%LOCALAPPDATA%\FamilyDashboard` (переопределяется `DASHBOARD_DATA_DIR`): `users.json` (пишет только CLI `scripts\user.cmd`; сервер его только читает), `logins.json` (время последнего входа; пишет только сервер — так CLI и сервер никогда не перезаписывают изменения друг друга), `sessions.json`, `services.json`, `audit.jsonl` (+ ротация), `backup-status.json` (появится с бэкапом), `logs\`, `run\`. Без СУБД: данных мало, запись атомарная (временный файл + rename); оставшиеся после внезапного отключения временные файлы сервер удаляет при старте.
3. **Будущие пользовательские данные** (фильмы, фото, документы) — отдельная корневая папка вне репозитория и вне профиля, например `C:\FamilyData\{Media,Photos,Files}`; каждый сервис — своя подпапка данных и конфигурации. Создаётся на этапе установки сервисов, не сейчас.
4. **Бэкап** не объявляется работающим, пока нет второго носителя и проверки восстановления. Копия на тот же диск защищает только от случайного удаления.

## Альтернативы

- SQLite — избыточна для десятков записей; добавила бы нативную зависимость.
- Данные внутри репозитория — риск случайного коммита персональных данных.

## Последствия

- Переустановка кода не трогает данные; удаление данных — отдельное осознанное действие.
- Каталог данных нужно включить в будущий бэкап (содержит хэши паролей — копировать только в зашифрованном виде вне ПК).
