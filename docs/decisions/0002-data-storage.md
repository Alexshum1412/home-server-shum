# ADR-0002. Где и как хранятся данные

- **Статус:** принято · 16.10.2026 · изменено 16.10.2026 (вечер): данные и инструменты перенесены из `%LOCALAPPDATA%` в `C:\FamilyServer`

## Контекст

Один рабочий диск `C:` (2 ТБ, ~1,8 ТБ свободно); второе устройство определяется как неисправное (`ST_M13FQBL`, 3,9 ГБ). Дашборду нужно хранить немного своих данных: пользователи, сессии, журнал аудита, список сервисов. Медиатека и фото будут у отдельных сервисов.

Первоначально данные лежали в `%LOCALAPPDATA%\FamilyDashboard`, а Node.js и Git — в `%LOCALAPPDATA%\Programs`. Выяснилось (16.10.2026), что приложение Claude Desktop — пакет MSIX, и у процессов, запущенных из него, записи в `%LOCALAPPDATA%` виртуализируются в `C:\Users\PC\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\`. Проверка, запущенная из Проводника, показала: ни старого Node.js, ни данных портала по обычным путям нет (`OLD_NODE=absent`, `OLD_DATA=absent`). То есть всё, установленное агентом в AppData, было невидимо для Проводника, Планировщика заданий и автозапуска. Подробно — `docs/environment-audit.md`, раздел 12.

## Решение

1. **Код** — только в `C:\Users\PC\Desktop\THE DASHBOARD` (Git).
2. **Единый корень сервера вне AppData — `C:\FamilyServer`** (в коде — `%SystemDrive%\FamilyServer`):
   - `tools\nodejs` — Node.js 24.22.0, npm 11.19.1, openspec; `tools\git` — Git 2.56.0.windows.2;
   - `data\dashboard` — данные портала;
   - `backups\` — резервные копии на основном диске (см. [ADR-0004](0004-backups.md)).
3. **Данные дашборда** — в `C:\FamilyServer\data\dashboard`: это значение по умолчанию на Windows и оно же явно задано в `.env` (`DASHBOARD_DATA_DIR`). Файлы: `users.json` (пишет только CLI `scripts\user.cmd`; сервер его только читает), `logins.json` (время последнего входа; пишет только сервер — так CLI и сервер никогда не перезаписывают изменения друг друга), `sessions.json`, `services.json`, `audit.jsonl` (+ ротация), `backup-status.json` (пишет задача копирования), `logs\`, `run\`. Без СУБД: данных мало, запись атомарная (временный файл + rename); оставшиеся после внезапного отключения временные файлы сервер удаляет при старте.
4. **Права NTFS:** на `C:\FamilyServer` — полный доступ у PC, SYSTEM и администраторов, у группы «Пользователи» — только чтение и выполнение (инструменты); на `data\` и `backups\` — только PC, SYSTEM и администраторы.
5. **Скрипты** (`scripts\common.ps1`, `scripts\user.cmd`, `scripts\backup.cmd`) берут Node.js из `C:\FamilyServer\tools\nodejs\node.exe`, если он есть.
6. **Будущие пользовательские данные** (фильмы, фото, документы) — отдельная корневая папка вне репозитория и вне профиля, например `C:\FamilyData\{Media,Photos,Files}`; каждый сервис — своя подпапка данных и конфигурации. Создаётся на этапе установки сервисов, не сейчас.
7. **Бэкап** — см. [ADR-0004](0004-backups.md): основной диск + флешка «reserve», с проверкой восстановления.

## Почему не AppData

- Виртуализация MSIX: файлы, записанные процессом из Claude Desktop, не видны остальной Windows — портал, запущенный из Проводника или Планировщика, не нашёл бы ни Node.js, ни свои данные.
- Один понятный корень проще копировать, проверять и описывать в ранбуках; права задаются один раз.
- Путь не зависит от профиля и от того, из какого приложения запущен процесс.

## Альтернативы

- SQLite — избыточна для десятков записей; добавила бы нативную зависимость.
- Данные внутри репозитория — риск случайного коммита персональных данных.
- Оставить `%LOCALAPPDATA%` и запускать всё только из Проводника — хрупко: любая установка из Claude Desktop снова ушла бы в виртуальную копию.

## Последствия

- Переустановка кода не трогает данные; удаление данных — отдельное осознанное действие.
- Старые копии Node.js, Git и данных внутри пакета Claude (`…\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Local\`) оставлены без изменений.
- Прежний user PATH сохранён в `C:\Users\PC\family-server-backups\userpath-backup-2026-10-16.txt`.
- Каталог данных входит в ежедневную резервную копию (содержит хэши паролей — копии хранить бережно, см. `docs/security.md`).
